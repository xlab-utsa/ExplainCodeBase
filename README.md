# Hierarchical Python Function Summarizer

A tool for automatically analyzing, graph mapping, and hierarchically summarizing functions in a Python codebase using LLMs.

## Installation

Install dependencies using `pip`:
```bash
pip install -r requirements.txt
```

Ensure the summarizer runner is executable:
```bash
chmod +x run_summarizer.sh
```

## Configuration

You can configure API credentials, custom model endpoints, and specific model versions by setting system environment variables or by creating a local `.env` file in the root directory.

### Configuration Options

- **Gemini**:
  - `GEMINI_API_KEY`: Gemini API client key (Required for Gemini).
  - `GEMINI_MODEL`: Gemini model name (Default: `gemini-2.0-flash`).
- **Anthropic Vertex**:
  - `PROJECT_ID`: Google Vertex Project ID (Required for Anthropic).
  - `VERTEX_LOCATION`: Vertex API region (Default: `us-east5`).
  - `ANTHROPIC_MODEL`: Anthropic model name (Default: `claude-3-7-sonnet@20250219`).
- **OpenAI**:
  - `OPENAI_API_KEY`: OpenAI API client key (Required for OpenAI).
  - `OPENAI_BASE_URL`: Optional custom base URL for OpenAI client.
  - `OPENAI_MODEL`: OpenAI model name (Default: `gpt-4o-mini`).
- **vLLM**:
  - `VLLM_API_KEY`: vLLM endpoint API key (Default: `EMPTY`).
  - `VLLM_API_BASE`: vLLM base URL endpoint (Default: `http://localhost:8000/v1`).
  - `VLLM_MODEL`: vLLM model name (Default: `openai/gpt-oss-20b`).

*Note: Environment variables set in the system shell take precedence over values defined in the `.env` file.*

## Usage

### Running the Summarizer

Run the summarizer using the shell script:
```bash
./run_summarizer.sh [folder_path] [model_choice]
```

- `folder_path` (Optional): The path to the Python codebase you want to analyze. If not provided (or if only the model choice is provided), the script looks for packages in the `input/` subdirectory.
- `model_choice` (Optional): The provider to use for inference. Options are `gemini`, `anthropic`, `openai`, or `vllm_models` (Default: `openai`).

#### Using the `input` Folder Option:
You can upload or place your Python codebase directories directly inside a local `input/` folder in the project root:
- E.g., place your package at `input/my_package/`.
- Then run the summarizer by specifying only the model:
  ```bash
  ./run_summarizer.sh gemini
  ```
  The script will automatically detect and process the package inside the `input/` folder.

#### Examples:
```bash
# Specifying folder path and model choice
./run_summarizer.sh ../my_package/ gemini

# Bypassing folder path to use the package under input/ directory
./run_summarizer.sh openai
```

### Running the Evaluator

You can run the evaluation script to compare the generated summaries across methods and models. It supports evaluating either all packages found in the summaries output directory, or a single specific package:
```bash
python3 evaluate.py [package_path_or_name] [model_choice]
```

- `package_path_or_name` (Optional): The path or name of a specific package to evaluate (e.g. `input/test_package` or `test_package`). If omitted, all packages are evaluated.
- `model_choice` (Optional): The model to use for performing the evaluation. Options are `gemini`, `anthropic`, `openai`, or `vllm_models` (Default: `openai`).

#### Examples:
```bash
# Evaluate all packages using vllm_models
python3 evaluate.py vllm_models

# Evaluate a single package using the default model (openai)
python3 evaluate.py input/test_package

# Evaluate a single package using vllm_models
python3 evaluate.py input/test_package vllm_models
```

## Outputs

All output files are saved locally under the `output/` directory:
- **`output/graph/`**: Stores the code dependency graph JSON file generated by `code2flow`.
- **`output/summaries/`**: Stores the final function-level and module-level summaries generated by the LLM models:
  - **`{package_name}_{model}_baseline.json`**: Baseline summaries (all code combined).
  - **`{package_name}_{model}_hucp.json`**: Hierarchical summary results (Method 1).
  - **`{package_name}_{model}_iucp.json`**: Inherited context summary results (Method 2).
  - **`{package_name}_{model}_llmucp.json`**: LLM-generated context summary results (Method 3).
  - **`{package_name}_{model}_docucp.json`**: Documentation context summary results (Method 4).
- **`output/evaluation/`**: Stores the evaluation results JSON files (e.g. `test_package.json`) for each processed package.
